## PR 1. 데이터 바로잡기 (`fix/campaign-attribution-spread`)

### 1) 광고 URL 태그 → 캠페인 자동 매핑

키워드 추측을 없애는 근본 수정이에요.

- `lib/meta.ts`에 `fetchAdUrlTags()`를 추가해요.
  - 요청: `GET /{ver}/{act}/ads?fields=id,campaign_id,creative{url_tags}&limit=500`
  - 필터는 effective_status 전체, 페이지는 끝까지 따라가요.
  - 페이징·에러 메시지·토큰 마스킹은 같은 파일 `fetchCampaignBudgets()`(533행) 패턴을 그대로 써요.
  - `url_tags`에 전체 URL이 들어간 광고도 있어서 `?` 뒤만 `URLSearchParams`로 읽어요.
  - 반환 형태: `{campaignId, camp, cont}[]`
- `lib/channel.ts` `byUtm`의 매칭 순서를 이렇게 바꿔요.
  1. 캠페인 ID 일치 (지금 그대로)
  2. (utm_campaign, utm_content) 둘 다 일치하는 광고
  3. utm_campaign만 일치하면 `campaigns` 순서(최근 광고비 순)에서 첫 캠페인
  4. 그래도 없으면 기존 키워드 규칙. 단 '연애운'을 **'연애'**로 바꿔요. 옛 4월 캠페인은 `campaignRefs`가 뒤로 보내요.
  - 함수 형태는 `classifyChannel(a, campaigns, tagRefs = [])`예요. 기본값이 있어서 `lib/mixpanel.ts` `isMetaUtm`(그룹만 판단)은 고칠 필요가 없어요.
- `lib/dashboard-cache.ts` 255행(`campaignRefs` 호출부) 근처에서 태그 표를 받아 `buildChannelPeriod` → `classifyChannel`로 넘겨요.
  - 캐시는 기존 5분 캐시를 따라요.
  - 실패하면 빈 배열로 대체돼서 지금처럼 키워드 규칙으로 동작해요.
